# README: Topological Accessibility and the 15-Minute City

This folder contains a proof of concept for evaluating 15-minute-city accessibility in Medellin using persistent homology. The implemented case study uses shopping malls and retail buildings as the service layer, builds a walking-time accessibility surface over a 100 m grid, and analyzes the topology of that surface with a cubical-complex filtration.

The central idea is to move beyond standard coverage metrics. Instead of only asking how much of the city is within 15 minutes of a service, the analysis asks whether the accessible area is connected, fragmented, or interrupted by persistent service voids.

## Research Question

Can persistent homology reveal the spatial structure of accessibility to shopping malls in Medellin, detecting fragmented access and service voids that standard 15-minute coverage metrics miss?

## Folder Contents

- `persistent_homology_malls.ipynb`: main notebook. It builds the grid, fetches shopping mall locations, computes walking time to the nearest mall, creates the filtration matrix, computes persistent homology, and generates visual outputs.
- `extract_centros_comerciales.ipynb`: exploratory notebook for querying shopping malls and retail buildings from OpenStreetMap through the Overpass API.
- `hospitals.ipynb`: exploratory notebook for loading health-provider data from Colombia's open-data portal and filtering records for Medellin. This is not yet integrated into the persistent-homology workflow.
- `medellin_drive_with_elevation.graphml`: OSMnx GraphML street-network file for Medellin. In the main notebook it is used to define the city/network geometry and map context.
- `walking_time_mall.parquet`: cached GeoDataFrame with grid cells and walking-time values. This avoids recomputing routing if the notebook is adapted to load it before the routing section.
- `figs/`: exported figures generated by the main workflow.
- `context.txt`: this README-style explanation.

## Main Workflow

The main implementation is in `persistent_homology_malls.ipynb`.

### 1. Load the Medellin Street Network

The notebook loads `medellin_drive_with_elevation.graphml` with OSMnx:

- Nodes: 15,207
- Edges: 36,725
- CRS: EPSG:4326
- Bounds: longitude -75.6445 to -75.5270, latitude 6.1773 to 6.3121

The network is converted to GeoDataFrames for nodes and edges. Its node geometry is then used to create a convex-hull approximation of the study area.

### 2. Build a 100 m Grid

The study area is reprojected to UTM zone 18N (`EPSG:32618`) so grid cells can be created in meters. A regular 100 m by 100 m grid is generated over the network hull and clipped to cells that intersect the city/network polygon.

Saved run:

- Grid cells before clipping: 19,370
- Grid cells retained inside the hull: 13,150
- Matrix dimensions: 149 rows by 130 columns

The grid centroids are converted back to WGS84 coordinates for routing.

### 3. Fetch Shopping Mall Locations

Shopping malls and retail buildings are fetched from OpenStreetMap using Overpass:

```overpass
nwr["shop"="mall"](6.14,-75.72,6.36,-75.45);
nwr["building"="retail"](6.14,-75.72,6.36,-75.45);
```

The notebook keeps elements with valid coordinates and names, using direct node coordinates when available and relation/way centers otherwise.

Saved run:

- Mall/retail POIs with names: 140

### 4. Compute Walking Time to the Nearest Mall

For every grid-cell centroid, the notebook computes pedestrian travel time to the nearest mall.

The original markdown mentions OSRM, but the implemented routing code uses Valhalla's public pedestrian routing service:

- Endpoint: `https://valhalla1.openstreetmap.de/sources_to_targets`
- Costing mode: `pedestrian`
- Batch size: 15 grid cells per request
- Delay between batches: 1.5 seconds
- Maximum retries: 4

The switch matters because the public OSRM `foot` endpoint was observed to return unrealistically fast times consistent with car routing. Valhalla's pedestrian costing produced more plausible walking speeds.

For each grid cell, the resulting accessibility value is:

```text
f(cell) = walking time from the cell centroid to the nearest mall, in minutes
```

Unreachable cells are assigned a sentinel value:

```text
SENTINEL = 120.0 minutes
```

In the saved run, no cells were unreachable.

Saved walking-time summary:

- Mean: 23.93 minutes
- Median: 17.95 minutes
- 25th percentile: 9.87 minutes
- 75th percentile: 34.73 minutes
- Maximum: 113.52 minutes
- Cells within 15 minutes: 5,660
- Cells within 30 minutes: 9,047

Since the city grid has 13,150 retained cells, the 15-minute coverage is approximately 43.0 percent.

### 5. Build the Filtration Matrix

The grid is converted into a 2-D matrix aligned by row and column indices. Each matrix entry stores the walking-time value of the corresponding grid cell.

Cells outside the study area are filled with the 120-minute sentinel, so they do not enter the meaningful filtration range.

The filtration is a sublevel-set filtration:

```text
A_t = {cell : f(cell) <= t}
```

As the threshold `t` increases, more grid cells enter the accessible region:

```text
A_5 subset A_10 subset A_15 subset A_20 subset A_30
```

The 15-minute threshold is treated as an interpretive benchmark inside the full persistence process, not as the only threshold.

### 6. Compute Persistent Homology

The notebook uses GUDHI's `CubicalComplex`:

```python
cc = gudhi.CubicalComplex(
    dimensions=list(filtration_matrix.shape),
    top_dimensional_cells=filtration_matrix.flatten().tolist()
)
cc.compute_persistence()
```

The persistence computation produces topological features in two dimensions:

- `H0`: connected components, interpreted as accessibility islands.
- `H1`: loops or holes, interpreted as potential service voids.

Saved persistence results:

- `H0` pairs: 773
- `H1` pairs: 382
- Finite `H0` pairs: 757
- Finite `H1` pairs: 333
- Mean finite `H0` persistence: 4.48 minutes
- Maximum finite `H0` persistence: 69.70 minutes
- Mean finite `H1` persistence: 2.79 minutes
- Maximum finite `H1` persistence: 23.10 minutes

The notebook also reports:

- `H0` features born before 15 minutes and dying after 15 minutes: 72
- `H0` features persisting beyond 30 minutes: 93

The most persistent `H1` service void in the saved run is born at 34.6 minutes and dies at 57.7 minutes, with 23.1 minutes of persistence. Several other `H1` features are born after 15 minutes and persist well beyond the 15-minute threshold.

## Interpretation

Standard coverage says that about 43.0 percent of the retained grid cells are within 15 minutes of a shopping mall or retail building.

Persistent homology adds information about shape:

- A high number of `H0` components means the accessible area is fragmented into disconnected islands rather than forming one continuous 15-minute fabric.
- `H1` features indicate holes in the accessibility surface: areas with poor access surrounded by areas with better access.
- Long-lived `H1` features are especially important because they suggest service voids that persist across many walking-time thresholds.

This means that two areas with similar 15-minute coverage could still have different accessibility structures. One may be continuous and redundant, while another may be broken into isolated clusters with internal gaps.

## How to Rerun

Run `persistent_homology_malls.ipynb` from this folder.

Required Python libraries include:

```text
numpy
pandas
geopandas
matplotlib
folium
shapely
osmnx
networkx
requests
gudhi
scipy
pyarrow or another parquet engine
```

The notebook requires internet access when it fetches data from Overpass and when it calls Valhalla for pedestrian routing. The routing step is slow because it sends hundreds of public API requests.

Important reproducibility note: `walking_time_mall.parquet` is saved as a cache, but in the current notebook the cache load/save cell appears at the end. To actually skip the routing API on reruns, move the cache-loading logic before the routing section or add a conditional branch around the routing loop.

## Current Limitations

- The implemented service layer is shopping malls and retail buildings, not the full set of essential 15-minute-city services.
- The city boundary is approximated from the network hull rather than using an official administrative boundary.
- Pedestrian travel times depend on the public Valhalla service and the state of OpenStreetMap data at query time.
- The GraphML file name indicates a drive network with elevation; the implemented walking-time computation itself comes from Valhalla pedestrian routing, not from shortest paths on this local graph.
- The `H1` spatial-localization step is a proxy based on cells whose filtration values fall inside important birth-death intervals. It does not yet extract exact homological generators.
- The `hospitals.ipynb` notebook is exploratory and has not yet been connected to the main persistent-homology pipeline.

## Next Steps

Natural extensions of this proof of concept are:

- Replace or complement malls with essential services such as clinics, schools, parks, grocery stores, pharmacies, and transit stations.
- Use official neighborhood, comuna, or district boundaries to compare topological accessibility across Medellin.
- Add population weighting to identify how many people live in persistent accessibility gaps.
- Compute travel time directly on a cleaned pedestrian network and compare it with Valhalla-based times.
- Add slope-adjusted walking time, which is especially relevant in Medellin's hillside neighborhoods.
- Turn the topological results into indicators such as fragmentation index, service-void index, and a combined topological 15-minute score.

## Key Takeaway

This folder demonstrates that the 15-minute city can be studied as a topological accessibility problem. The result is not only a percentage of cells within 15 minutes of a service, but a description of whether access forms a continuous urban fabric or a fragmented landscape with persistent service voids.
